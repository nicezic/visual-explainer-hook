# HISTORY: why the hook is shaped the way it is

Read this before changing anything. It records how the design evolved, the reason behind each decision, and the mistakes an agent already made here, so a new session does not repeat them.
How it runs now: [README.md](README.md). Fork upkeep: [../README-DOWNSTREAM.md](../README-DOWNSTREAM.md).

## The goal (why this exists)

- **Cut Claude usage.** The parent (Claude Code) should eventually write short, record-style replies. Cheaper models via pi (lineup: the `models` file, decision 13) turn each finished turn into a visual-explainer (VE) page for the human.
- The hand-off costs the parent zero tokens: the hook reads the reply and the transcript from disk.
- **The savings only start at stage 3** (shorter parent replies), which has not started. Everything so far makes the explainer good enough to justify that step.

## Early decisions (00:55-05:45, still in force)

- **Delivery by the hook, never by the parent.** If the parent re-sent "input + reply" itself, output tokens would double.
- **The explainer's output never goes back into the log;** the log holds the parent conversation plus one `→ page:` line per page (the explainer's own journal keeps its pages: decision 5).
- **pi, not codex CLI:** open source, and it runs the user's subscriptions. MiniMax runs on the user's subscription (`creds run ai --`), never OpenRouter (proposing it annoyed the user).
- **Pages auto-open** (the user expected them to pop up). **No reply-length filter:** it would block "explainer, explain X" turns once parent replies are short.
- **Taking tools away works better than asking nicely:** moving rules + docs into the system prompt and allowing only `read,write` took M3 from 183 s / 8 steps to ~13 s / 2 steps.
- pi facts: `--no-context-files`, `--tools <allowlist>`, `--session <path>`; `--session-id` continues a session (not a cache knob); compaction triggers at contextWindow − 16,384.

## Mistakes already made here: do not repeat

1. **Guessing causes and presenting them as findings.** "MiniMax routes to other servers" and "the TTL is short" were stated without evidence; the user rejected both, rightly. A cheap control (the 10-turn plain test, then byte-identical replays) showed the server was fine and our request shape was the cause. Measure and compare against a control before naming a cause.
2. **Ignoring warnings already in the logs.** "Visual check skipped" sat in `run.log` 169 times. Read the tool's own warnings first.
3. **Editing history in an append-only journal** to save context breaks the prefix cache (measured). Cap and restart instead (decision 6).
4. **Changing `contract.md`, the doc list, or a preloaded VE doc (SKILL.md, a reference) without restarting live journals.** pi keeps the old system prompt at the top and appends only a patch, so the model sees both versions (`agent-session.ts:1820`). Move `sessions/*.jsonl` aside and empty the `.pos` files, each under its `.pos` flock (`flock <pos> …`): a run in flight re-opens the journal by path and would leave a headerless fragment.
5. **Over-installing.** A plain `pnpm install` pulled 158 packages (195 MB) where only the devDependency playwright-core (14 MB) was needed. Also, `import()` never looks at global installs, so a mise or npm global install cannot serve `look.mjs`.
6. **A check that silently does not run counts as a pass.** The visual check only runs on kit pages, so "did the check run?" must be a failure condition too. Decision 8 covers a missing kit marker; a visual check skipped for a missing playwright-core is logged as `ERROR visual check skipped: <page>` in run.log since `67af533` (the explainer cannot fix it).
7. **Committing or amending after every small edit.** Keep edits in the working tree. Shape logical commits once, right before a push, and show the commit plan first.
8. **Saving Claude memory files unasked.** The user deleted them. Keep continuity in the repo docs (this file, README.md, README-DOWNSTREAM.md).
9. **Explaining with undefined jargon.** The user asked for friendlier, junior-developer-level explanations: define terms on first use, use tables and one picture-like layout, and keep it short.
10. **Writing claims or changing docs before checking the source.** On 2026-11-14/15 an agent: called upstream "Claude-only" (it is a general agent skill: Claude Code, pi, Codex, Cursor, MCP…); said PR #105 was "tuned for Claude" (it replaced Mermaid with SVG); dropped `motion.md` as an "SVG manual" (it is the stepper/replay doc `<ve-flow>` uses); wrote `<ve-flow>` where the idea is auto-layout in general; and credited a docs change for a result that came from the loading setup. On 2026-11-26 an agent proposed upstream PRs from merged diffs alone; the maintainer's PR comments had already rejected SVG-last on purpose (#137). Read the PR and issue comments before proposing upstream work. Read the upstream file, commit or data first, then write. Keep public text short and soft; numbers only when asked.
11. **Acting on the agent's own conclusion instead of the user's words.** On 2026-11-15 an agent decided unasked not to send PR ②, lost its rationale (efficiency) while summarizing, wrote `<ve-flow>` in public text the user wanted as "auto-layout", and added an SVG send-back check nobody asked for (against decision 14). Restate the request in one line ("understood: …; will do: …") and get an OK before changing state.
12. **Copying upstream VE rules into `contract.md`, restarting journals after every small edit, and acting on the wrong file.** On 2026-11-15 an agent restated SKILL.md rules in the contract (the user: it is already upstream), restarted the live journals after each one-line contract edit (each restart resends the whole log and burns tokens), and reverted upstream lines when the user meant `CLAUDE.md`. Keep the contract to what the docs do not say, batch edits and restart once, and confirm the file path when unsure.

## Working agreements (still in force)

- Reply in Korean, short and scannable, keeping English tech terms. Discussion first, then the smallest complete change.
- Ask before changing `~/.claude/settings.json` or the model lineup.
- When a turn is addressed to the explainer ("Claude, do nothing; M3, …"), the parent does nothing; the request reaches M3 through the log.
- The repo is public: no conversation data, keys, or emails in it.
